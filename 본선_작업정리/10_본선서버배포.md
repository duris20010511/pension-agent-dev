# 10. 본선 서버 배포

예선과 같은 방식(네이버클라우드 서버 + Docker, 80번 포트)으로 올립니다. 다른 점은 수정할 때마다 `deploy/deploy.sh push` 한 번으로 다시 올린다는 것입니다. 묶기, 전송, 빌드, 교체, 확인을 한 번에 하고, 새 판이 3분 안에 뜨지 않으면 이전 판으로 되돌립니다.

## 사람이 할 일 (처음 한 번)

결제가 따르는 계정 작업이고 비밀번호와 키를 다루는 단계라, 아래 1~3은 직접 해 주세요.

### 1. 서버 만들기 (네이버클라우드 콘솔)

| 항목 | 값 | 이유 |
|---|---|---|
| 이미지 | Ubuntu 22.04 또는 24.04 | 실제 실행은 컨테이너 안의 python:3.11-slim |
| 서버 타입 | Standard 2vCPU 4GB 이상 | 색인·임베딩을 메모리에 올림. 1GB는 기동 중 메모리 부족 위험 |
| 스토리지 | 30GB | 기본 10GB는 Docker 이미지·빌드 캐시로 부족 |
| 공인 IP | 신청 후 이 서버에 할당 | 시연·평가 주소가 됨 |
| ACG 인바운드 | TCP 80 `0.0.0.0/0`, TCP 22 본인 IP `/32` | 22는 본인만 열기 |

**주의:** `/demo`와 `/chat`이 공인망에 열리면 아무나 CLOVA 키의 한도를 쓸 수 있습니다. 시연 장소 IP나 주최측 대역이 정해지면 80번 규칙도 그 대역으로 좁히는 것이 안전합니다.

### 2. 배포 키 등록 (서버에 처음 접속해서)

콘솔에서 확인한 관리자 비밀번호로 처음 한 번 접속한 뒤, 아래 공개키를 등록합니다. 그다음부터 배포 스크립트는 비밀번호 없이 이 키로 접속합니다. 개인키(`~/.ssh/pension_deploy`)는 이 PC에만 있습니다.


### 3. 키 파일(.env) 올리기 (이 PC에서)

```bash
scp -i ~/.ssh/pension_deploy .env root@<공인IP>:/root/.env
```

## 배포 (Claude 가 하거나, 직접)

```bash
bash deploy/deploy.sh setup <공인IP>
```

```bash
bash deploy/deploy.sh push <공인IP>
```

- `setup`: 처음 한 번 Docker를 설치하고 폴더를 만듭니다.
- `push`: 지금 코드로 배포합니다. 판 이름은 `커밋-시각`이고, 커밋 안 된 변경이 있으면 `-dirty`가 붙습니다. `http://<공인IP>/health`의 `version`으로 어떤 코드가 올라갔는지 확인합니다.
- `status`, `logs`: 돌고 있는 판과 로그를 봅니다.
- 묶음은 약 35MB입니다. 코드와 문서, 추출본, 지금 지문(`cf1e5f2bfc45_v3`)의 색인·임베딩 캐시 두 파일만 넣습니다(`.cache` 전체 426MB 중 약 70MB).
- 서버 로그는 `/root/logs`(컨테이너의 `/app/logs`)에 쌓입니다.
